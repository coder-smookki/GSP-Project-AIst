# Загрузка корпуса по API базы знаний

Как получить доступ, куда положить учётные данные, что именно приходит по сети
и чем статья API отличается от файла `.docx`.

Про сам конвейер разбора и нарезки — [docs/INGEST.md](INGEST.md).

## Доступ

Учётную запись выдаёт организатор кейса; самостоятельной регистрации в базе
знаний нет. Нужны три вещи: адрес, почта и пароль.

| Переменная | Что это | Пример |
| --- | --- | --- |
| `KB_BASE_URL` | Корень API | `https://hihub.ru/` |
| `KB_EMAIL` | Почта учётной записи | `user@example.com` |
| `KB_PASSWORD` | Пароль | — |
| `KB_SECTION_ID` | Раздел с материалами кейса | `44030` |
| `KB_TOKEN_NAME` | Произвольная метка токена, требуется при входе | `aist` |

Кладутся в `deploy/.env`, который **закрыт `.gitignore`**. В репозиторий пароль
не попадает никогда и в логи тоже: у поля `password` в конфигурации стоит
`repr=False`, а тесты отдельно проверяют, что пароль не просачивается в текст
ошибки.

Проверить доступ, ничего не индексируя:

```bash
uv run python scripts/ingest.py --source api --dry-run --limit 3
```

## Что происходит по сети

Три обращения, все относительно `KB_BASE_URL`.

**1. Вход.** `POST api/auth/logininng`

```json
{"email": "...", "password": "...", "token_name": "aist"}
```

В ответ приходят `access_token` и, если сервер его выдаёт, `refresh_token`.
Ответ без `access_token` считается неудачей входа: иначе клиент пошёл бы
дальше без токена и упал бы позже, с непонятным сообщением.

**2. Перечень статей раздела.** `GET api/knowledgebase/section/{id}/articles`
с параметрами `page` и `per_page`.

Обход постраничный и управляется полем `meta.last_page` — по числу элементов
на странице останавливаться нельзя. Предохранитель на 1000 страниц: сервер с
постоянно растущим `last_page` увёл бы обход в бесконечный цикл.

**3. Статья целиком.** `GET api/knowledgebase/article/{id}`

Объект лежит в поле `data`: `id`, `name`, `content` (HTML), `section_id`,
`updated_at`. Отсутствие `data` — поломка протокола, а не пустая статья, и
она поднимает `TransportError`.

### Токен и повторы

Токен живёт меньше, чем идёт полная индексация, поэтому на `401` клиент
входит заново и повторяет запрос — сам, один раз. Одновременные `401` не
плодят параллельных входов: обновление идёт под блокировкой.

Временные ошибки (`5xx`, обрыв связи) повторяются с экспоненциальной паузой,
число повторов ограничено `KB_MAX_RETRIES` (по умолчанию 3). Индексация идёт
десятками минут, и разовая пятисотка не должна стоить всего прогона; но
повторы конечны — устойчивый отказ доходит до вызывающего.

## Чем статья API отличается от файла

| | Статья API | Файл `.docx` |
| --- | --- | --- |
| Что приходит | HTML в поле `content` | путь к файлу, читает сам разбор |
| `doc_id` | идентификатор статьи | идентификатор из источника |
| `doc_code` | выводится из порядкового номера в названии | из имени файла и титула |
| `updated_at` | из ответа сервера | время изменения файла |
| Таблицы | теги `<table>`, `<tr>`, `<td>` | границы `w:tbl` в разметке Word |

Общее: оба формата приводятся к одному `ParsedDocument`, и дальше конвейер их
не различает. Разница живёт только в разборе.

**Про таблицы честно.** В обоих форматах табличная разметка теряется: текст
ячеек вытягивается подряд, а сама сетка — нет. Границы таблиц размечаются, и
номера пунктов внутри них считаются недостоверными: лучше отдать ссылку на
раздел, чем неверную ссылку на пункт.

## Загрузка

### Из командной строки

```bash
uv run python scripts/ingest.py --source api --switch-alias
```

Разбор без записи в индекс — `--dry-run`. Ограничить число документов —
`--limit N`; при этом алиас **не переключается**: поколение заведомо неполное.

### Через Prefect

```bash
docker compose -f docker-compose.yml -f docker-compose.orchestration.yml up -d
```

Интерфейс на `:4200`. Поток `ingest_flow` берёт те же переменные из
`deploy/.env`, что и командная строка, — отдельной настройки у него нет.
Видно, какой документ разобран, какой упал и почему; прогон повторяется из
интерфейса.

## Если правился разбор или нарезка

Отпечаток документа считается по его содержимому, а оно при правке кода не
меняется — прогон сочтёт всё неизменившимся и ничего не переиндексирует.
Чтобы этого не случилось, в отпечаток входит `pipeline_version`
(`infrastructure/ingest/config.py`). **Изменили разбор или нарезку — поднимите
версию**, иначе исправление не доедет до индекса.

По той же причине в отпечаток входит имя модели эмбеддингов: векторы разных
моделей несовместимы по смыслу даже при равной размерности.

## Что проверяется тестами

`tests/test_infrastructure/retrieval/test_kb_client.py` — на подменённом
транспорте, без сети и без настоящих учётных данных, поэтому идёт в обычном
прогоне:

- вход запоминает токен; ответ без токена — ошибка входа;
- пароль не попадает в текст ошибки;
- постраничный обход доходит до последней страницы;
- раздел берётся из настройки;
- статья достаётся из `data`, её отсутствие — ошибка протокола;
- временная ошибка повторяется, повторы ограничены;
- истёкший токен вызывает ровно один повторный вход.

Прогон живой загрузки (нужны доступ и сеть) помечен маркером и в обычный
прогон не входит.
